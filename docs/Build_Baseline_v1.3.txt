# 2. Conflicts and risks, and how we build them
Answers that clash with each other or with agreed rules. Each is built as shown, so development is not blocked.
| # | Conflict | What we build | Why it matters |
| 1 | S6.1 lists PAN and bank statements as sanction records. That breaks agreed rule 10 (no KYC on the platform). | Not stored. Ecofy keeps KYC on its systems; the platform records status, amount and date. | Holding a lender's KYC makes iTarang liable for regulated financial data under DPDP, with audits and breach risk, for no revenue. |
| 2 | Consent “through an agreement” (S0.4, L.3), while Appendix A keeps per-lead consent mandatory. | Keep per-lead consent flag and date mandatory, plus a logged confirmation at each upload, plus warranty and indemnity from Ecofy in the agreement. | An agreement between two companies moves liability; it does not create the customer's consent. If Ecofy has no per-lead consent dates, uploads will be rejected: surface this before go-live. |
| 3 | Installation can start before sanction (S6.4), and payout happens after installation (S7.1). | Gate off as answered; the platform warns iTarang Admin when installation starts without sanction. | An installed system that Ecofy then rejects is unfunded. W.2 says Ecofy covers EPC cancellation charges; confirm that also covers a rejection after installation. |
| 4 | The caller cannot see the eligible amount (S4.6) but must sell within it. | Caller sees “quote within limit” or “above limit”, never the number. | Without it, quotes above the limit get accepted, then cut at sanction, forcing a fresh acceptance and often losing the customer. |
| 5 | Fresh acceptance after a lower sanction (S6.2), but the caller cannot see amounts and Ecofy collects the down payment. | Ecofy Admin triggers the re-acceptance. The customer's SMS carries the financed amount and down payment; the caller sees status only. | Needs a new DLT SMS template with amount variables. Apply now: DLT approval takes days, and the current template likely has no amount fields. |
| 6 | Another financier after rejection (S6.3), and iTarang-owned leads financed by any NBFC (C.4). | Financier field on every case (Ecofy by default). iTarang Admin routes and records other financiers' decisions; no financier logins. | The Ecofy workspace will hold cases financed by others. Default: Ecofy sees a case once it is the financier or the lead source. Whether Ecofy earns anything when its lead is financed elsewhere is open. |
| 7 | Appendix A vs answers: ecofy_lead_id marked mandatory, but Ecofy has no ID (L.4); assign_to removed, but both assignment options wanted (L.5). | Both kept, as optional columns. | Otherwise every upload fails on a column Ecofy cannot fill, and in-file assignment is impossible. |

| 9 | No sample of Ecofy's lead data yet (L.1). | Column mapping on the upload screen. | The first real upload is when mismatches show up; mapping stops that becoming a platform failure. |

# 4. Calculator Designer
iTarang Admin designs the calculator in the portal by setting its parts: inputs, appliances, values, rules and texts. The formula itself is fixed and tested. A free-form formula editor is not in V1: one wrong formula silently mis-sizes every customer, and it cannot be tested before customers see it. If a real need for a new step appears, we add it to the fixed formula as a new setting.
## What the admin controls
| Part | What the admin can change | Default |
| Segments | Turn the calculator on or off per segment; set the message shown where it is off. | RESI on, ESS on, C&I off (“EPC quote required”) |
| Input methods | Which inputs each segment offers. Backup hours and phase are always asked. | RESI: appliance list or monthly units. ESS: appliance list, monthly units or running load |
| Appliance list | Add, remove or rename appliances; set default watts, whether it is a motor load, its starting multiplier, and the display order. | 14 confirmed appliances; motor loads listed below |
| Values | Every number the formula uses. | See the values table |
| Recommendation rules | How many smaller and larger alternatives (0–2 each); which sizes must be covered; phase must match. | 1 smaller + 1 larger of the same type; system type follows product interest; phase must match |
| Display and texts | Price display (range or hidden); separate GST and installation lines; disclaimer, financing line, “custom configuration required” message. | Range, with separate lines |
| Test bench | Enter sample inputs and see every step's result before publishing. The worked example below is preloaded. | On |
| Versions and approval | Edits are saved as a draft, tested, approved by Ecofy Admin, then published. Every saved assessment stores the version it used. Any earlier version can be restored. | Ecofy approval required |

## The fixed formula
| # | Calculates | Method |
| 1 | Running load (kW) | Watts × quantity for each appliance, added up, ÷ 1,000. Or the running load entered (ESS). Bill only: sanctioned load. |
| 2 | Backup energy (kWh) | Running load × backup hours. Bill only: (monthly units ÷ days in a month) × backup hours ÷ 24. |
| 3 | Usable battery needed (kWh) | Backup energy ÷ inverter efficiency. |
| 4 | Battery size shown (kWh) | Usable battery needed ÷ usable share of the battery. |
| 5 | Motor starting power (kW) | Largest motor load's watts × (its starting multiplier − 1) ÷ 1,000. Zero if no motor or bill only. |
| 6 | Inverter size (kVA) | (Running load + motor starting power) × (1 + surge headroom) ÷ power factor. |
| 7 | Solar size (kWp), residential | (Monthly units ÷ days in a month) ÷ solar generation per kWp per day. |
| 8 | Recommendation | Smallest active standard system for the segment, phase and type (from product interest; Not sure = all types) that covers the need: Solar + storage checks usable capacity, inverter and solar; Storage only checks usable capacity and inverter; Solar only checks solar kWp (backup hours not asked). Plus the alternatives set in the rules. Three results: RECOMMENDED; CUSTOM_REQUIRED when the need is known but nothing fits (routed to an EPC quote); PENDING_TECHNICAL_DATA when a need cannot be computed for lack of input, never shown as custom. |
| 9 | Price shown | For each system: equipment range + installation range, then GST at the system's rate, each on its own line. No EMI. “Financing through Ecofy, subject to sanction”. |

## Values
| Value | Default | Source |
| Usable share of the battery | 90% | Business (was 80%) |
| Inverter efficiency | 90% | Business |
| Surge headroom | 10% | Business (was 25%) |
| Power factor | 0.8 | Business |
| Motor starting multiplier: refrigerator, both ACs, water pump | 3× | Our default (C.7) |
| Motor starting multiplier: washing machine, mixer grinder | 2× | Our default (C.7) |
| Solar generation per kWp per day | 4 units | Our default |
| Days in a month | 30 | Our default |

## Worked example with the business values
| Home with 4 fans, 6 LED bulbs, 1 TV and 1 refrigerator; 4 hours of backup; 300 units a month / Running load = 4 × 75 + 6 × 10 + 100 + 200 = 660 W = 0.66 kW / Backup energy = 0.66 × 4 = 2.64 kWh  →  usable battery needed = 2.64 ÷ 90% = 2.93 kWh  →  battery shown = 2.93 ÷ 90% = 3.26 kWh / Motor starting power = refrigerator 200 W × (3 − 1) = 0.40 kW / Inverter = (0.66 + 0.40) × 1.10 ÷ 0.8 = 1.46 kVA  ·  Solar = (300 ÷ 30) ÷ 4 = 2.5 kWp / Against the review pack: battery 3.67 → 3.26 kWh (90% usable); inverter 1.03 → 1.46 kVA (motor starting now counted). |
